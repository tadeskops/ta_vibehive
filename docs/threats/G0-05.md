# Threat model · Slice G0-05 (OWASP Top-10 baseline hardening)

Per `AGENTS.md §4.1`: every module ships with a five-line threat model.

1. **Assets in scope.** `tests/owasp.test.js` (14 assertions run against workspace or built `_site/`), updated CI workflow (adds strict-CSP + banned DOM sinks + XCTO/Referrer-Policy/Permissions-Policy grep), updated `scripts/check-sec.ps1` (local mirror).
2. **Trust boundaries.** CI runner ↔ workspace/artefact. No new runtime code — this slice is entirely a hardening + verification pass.
3. **Top risks (mapped to OWASP Top-10 2021).** A01 Broken Access Control — deferred to G1-04 server-side write path; A02 Cryptographic Failures — no plaintext secret regex asserted; A03 Injection / XSS — strict CSP, no inline JS/events, no `x-html`, no `innerHTML=/outerHTML=`, no `document.write`, no `eval`/`new Function`; A04 Insecure Design — SSRF surface = zero because no server; A05 Security Misconfig — 4 mandatory meta headers on every HTML; A06 Vulnerable Components — SRI on every vendored `<script>`, only pinned lib is Alpine 3.14.1; A07 Auth Failures — see G1-04; A08 Software/Data Integrity — vendored SRI + gitleaks + no LLM SDK markers; A09 Logging Failures — audit-log-lite chain integrity asserted; A10 SSRF — none possible on static Pages.
4. **Assumptions.** GitHub Pages default TLS + HSTS trusted. GitHub Actions runners trusted. jsDelivr trusted only at vendor time. Modern browsers (CSP L3, Trusted Types coming G3-01). No third-party analytics on the shipping path.
5. **Follow-ups.** (a) Add Trusted Types policy in G3-01. (b) Add semgrep in G1-01. (c) Add nightly gitleaks history scan in G3-01. (d) Add `_headers` file for Cloudflare Pages compatibility if hosting ever moves.
