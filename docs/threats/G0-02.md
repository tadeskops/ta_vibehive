# Threat model · Slice G0-02 (Base layout + Alpine + 2-role RBAC constants)

Per `AGENTS.md §4.1`: every module ships with a five-line threat model.

1. **Assets in scope.** `index.html` (Alpine-bound shell), `assets/css/base.css`, `assets/js/app.js` (shell store + language toggle), `assets/js/rbac.js` (client-side role map), `assets/vendor/alpine-3.14.1.min.js` (vendored). No auth, no user data yet.
2. **Trust boundaries.** Browser JS ↔ localStorage (language pref only). Browser ↔ Pages CDN (static assets over TLS). CI ↔ vendored artefact (SHA-384 verified at ship time).
3. **Top risks.** (a) Supply-chain compromise of Alpine.js — mitigated by SRI attribute `integrity="sha384-…"` on the `<script>` tag + repo-committed hash in `assets/vendor/HASHES.md`. (b) Client-side RBAC treated as security by future slices — mitigated by explicit comment in `rbac.js` + server-side re-check requirement recorded here. (c) XSS via Alpine `x-html` bindings — mitigated by CSP `script-src 'self'` + code rule "no `x-html`" enforced in G4 CI grep from G0-05. (d) localStorage pollution — bounded (single `tvh.lang` key, allowlist of 3 values).
4. **Assumptions.** Alpine 3.14.1 is trusted for the launch window; upgrade needs a new SHA-384 in HASHES.md + a fresh vendor script run. jsDelivr CDN is trusted **only** at vendor time, never at runtime (CSP blocks CDN fetches).
5. **Follow-ups.** (a) Add Playwright screenshot test for palette + hero card + language toggle in G0-02.1. (b) Enable Dependabot for the workflow files. (c) Add a CI check that `x-html` is not used anywhere in the codebase (G0-05).
